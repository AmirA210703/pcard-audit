Ask a question about the P-card data

Type a question the way you would ask a colleague. The question is sent to {% if nl_provider == 'gemini' %}Gemini{% elif nl_provider == 'anthropic' %}Claude{% else %}a language model{% endif %}, which writes a SQLite query against the transaction table; the server then runs that query in read-only mode and shows you the answer and the query, so you can check the logic before you rely on it. Nothing you do here can change the data. Only the table definition and your question are sent to the model — no transaction data leaves this server.

Prohibited-purchase dashboard

    
How to use this dashboard

    
    
      
  1. Choose the year you are auditing. The 2014 calendar year is the year
          under audit; earlier years are available for trend work.
    2. 
      
  2. Pick a prohibited category from the list below. Clicking a term loads it
          into the search box it belongs to — description terms into the description search,
          vendor terms into the vendor search — and runs the search.
    3. 
      
  3. Or type your own keyword. Use the description search to look
          inside the merchant's line detail (for example gift card), and the
          vendor search to look at the merchant name (for example postal).
          Matching is case-insensitive and partial, so liquor also finds
          PARKHILL'S WAREHOUSE LIQUOR.
    4. 
      
  4. Set a minimum amount to push small, low-risk charges out of the way.
    5. 
      
  5. Read the category note before you act. Every category has known false
          positives, and they are listed there.
    6. 
      
  6. Export to CSV to carry the population into your working papers.
    7. 
    

    

      A hit is a lead, not a finding. Descriptions are supplied by the merchant, are often just
      GENERAL PURCHASE, and cannot be relied on alone — obtain the receipt and the
      business purpose recorded in Works before concluding that a purchase was prohibited.
